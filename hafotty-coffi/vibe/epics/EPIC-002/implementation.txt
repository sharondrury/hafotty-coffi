Feat-002 | Basket Context — Per-Item Milk Choice
--------------------------------------------------
File:
  hafotty-coffi/src/website/components/basket/basketContext.jsx

What was implemented:
  Two new actions added to the existing context:

  addItem(item, milkChoice = 'Full Fat')
    — Works like addToBasket but stores milkChoice on each basket entry.
    — If item already exists, increments quantity AND updates milkChoice to the
      latest selection (so changing the pill then clicking + keeps things in sync).

  updateMilkChoice(id, milkChoice)
    — Maps over basket and updates the milkChoice of the matching item.
    — Called by CoffeeCard when the user selects a different milk pill and the
      item is already in the basket.

  Both new actions exposed in the Provider value alongside existing ones.
  Existing addToBasket / updateQuantity / removeFromBasket / clearBasket retained
  unchanged — teaType and other consumers are unaffected.
  Global milkChoice / setMilkChoice retained for tea's global milk selection.

Why two separate add functions:
  addToBasket is used by teaType (no per-item milk). addItem is used by coffeeType
  (per-item milk). Keeping both avoids a breaking change to teaType.

Feat-003 | CoffeeCard Sub-Component with Milk Pills
-----------------------------------------------------
File:
  hafotty-coffi/src/website/pages/coffeeType/coffeeType.jsx
  hafotty-coffi/src/website/pages/coffeeType/coffeeType.scss

What was implemented:
  CoffeeCard extracted as a named function (not exported) inside coffeeType.jsx.
  This keeps the file under the 250-line limit and follows single responsibility.

  Local state pattern:
    const basketItem = basket.find(i => i.id === coffee.id)
    const [localMilk, setLocalMilk] = useState(basketItem?.milkChoice ?? 'Full Fat')

  localMilk initialises from the basket entry if the item is already there, so
  returning to the page after adding an item shows the correct selected pill.

  Milk pills (MILKS constant above the component):
    ['Full Fat', 'Skimmed', 'Oat', 'Soy', 'None']

  handleMilkSelect(milk):
    - Always updates localMilk state.
    - If qty > 0, also calls updateMilkChoice to keep basket in sync.

  + button: calls addItem(coffee, localMilk)
  − button: calls updateQuantity(coffee.id, qty - 1) — unchanged

  CoffeeType parent is now a thin wrapper: reads only basketCount, renders
  the header bar and maps CoffeeCard. All card logic is in CoffeeCard.

Tradeoffs and follow-up tasks:
  - EPIC-003 (teaType) still uses addToBasket + global milkChoice. A future
    revision could add per-card milk pills to tea in the same pattern used here.
  - localMilk in CoffeeCard initialises once from the basket. If the basket is
    modified from another card or page and then the user returns, the pill state
    is re-initialised from the basket on mount (correct). Mid-render changes from
    external sources won't update the pill — acceptable for this scope.
  - addItem and addToBasket do slightly different things. If a refactor is ever
    needed, addToBasket could be replaced everywhere by addItem with no milk.
